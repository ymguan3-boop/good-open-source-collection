# 宜蘭縣道路工程重複施工查核分析

## 主要發現

本次以宜蘭縣公開道路挖掘資料進行查核篩選，分析期間為 **2023-09-25 至 2026-09-25**。公開來源共解析 **66 筆案件**，其中 **53 筆**同時具備分析期間內的日期與可計算空間幾何；另有 13 筆位於分析期間外。

依使用者已確認的規則，以施工幾何在 TWD97 / TM2 121 分帶（EPSG:3826）中 **50 公尺內**建立空間關聯，且同一群聚至少 **2 件施工**才列入查核熱點；另檢查後案開工日是否落在前案完工後 **180 天內**。

結果共找到 **2 處重複施工查核熱點**，但 **0 處符合「前案完工後 180 天內再次施工」**的短期重複施工條件。這代表本次公開資料可用來挑出值得進一步調卷的空間群聚，但不能僅憑本成果認定已有資源浪費、違失或不當施工。

## 拿什麼資料

### 主要資料

本次核心資料來自**宜蘭縣道路挖掘公開 XML**，透過 ODPortal 的 resourcedata 代理／預覽端點取得。資料中包含案件編號、工程名稱、道路、施工日期、單位，以及 GML 施工多邊形／中心點。此次取得內容可見更新至 **2026-09-24** 的案件。

- 提供者：宜蘭縣政府道路挖掘公開資料
- 取得管道：ODPortal resourcedata
- 主要端點：https://cdn.odportal.tw/api/v1/resourcedata/DSNTMGUM/61b504bb6e97860024674b09.csv
- 幾何座標：原始 GML 使用 EPSG:3826
- 在分析中的用途：施工日期、施工範圍／中心點、道路名稱、案件與單位辨識

### OSM 道路中心線

原流程原先規劃以 OpenStreetMap / Overpass 補充道路中心線，但因第三方服務曾出現逾時，本次正式核心判定已改為**直接使用宜蘭公開 XML 的 GML 幾何與 DG_ROAD / DG_ROAD2 道路欄位**。因此 roads-context.geojson 本次為空的輔助圖層（0 features），不參與 2 個熱點的判定，也不影響結果。

## 怎麼比

1. 先把 66 筆公開案件解析為個別 CASE_DETAIL。
2. 使用 GML 施工多邊形；若案件沒有多邊形則使用中心點。
3. 統一以 EPSG:3826 進行公尺制距離計算。
4. 排除分析期間外案件；本次保留 53 筆。
5. 任兩件施工幾何距離不超過 50 公尺，即建立空間關聯。
6. 以關聯形成空間群聚，群聚至少 2 件才列為重複施工查核熱點。
7. 再比較時序：後案開工日距前案完工日 0～180 天者，標示為「短期再次施工」。
8. 本次 2 個群聚皆未出現符合 180 天規則的案件對。

這裡的「50 公尺群聚」代表**空間上鄰近**；「180 天內再次施工」才代表額外的**時間條件命中**。兩者不可混稱。本成果只做查核篩選，不等同法定風險、違失認定或浪費認定。

## 資料限制

1. 公開 XML 本次解析到 66 筆，不能推論縣府內部道路挖掘管理系統近 3 年完整母體只有 66 筆。
2. 「道路養護工程／管線工程」部分分類依工程名稱、用途與單位文字判斷，正式查核仍應回查原始案件。
3. 50 公尺代表幾何鄰近，不代表兩件工程必然挖到完全相同的路面。
4. 兩個熱點都沒有命中 180 天短期再次施工條件，因此不能把它們直接稱為短期重複開挖。
5. 是否存在不當施工、資源浪費或行政責任，仍需查閱施工必要性、緊急搶修、整合施工紀錄、契約、許可及現場資料。

## 總結

依目前可取得且可驗證的公開宜蘭道路挖掘資料，本次找到 **2 處 50 公尺內重複施工空間群聚**，其中 **0 處**符合「前案完工後 180 天內再次施工」條件。RC-0001 因共有 5 件施工集中於相近範圍，較適合作為後續人工調卷與施工整合查核的優先對象；RC-0002 則應先確認是否為同一工程、相鄰工區或同日整合施工。

本成果的定位是**審計選案與查核篩選工具**，不是違失結論。後續若能取得縣府內部完整道路挖掘歷史資料，可沿用相同 50 公尺與 180 天規則重新運算，將本模型升級為較完整的全縣查核母體分析。
