日期：2026-10-07，Asia/Taipei。瀏覽器入口維持 `http://127.0.0.1:4175/`，沿用既有 Node provider 與 DPAPI 金鑰。

## 交付功能

| 位置 | 操作 | 成果 |
| --- | --- | --- |
| 專案 → 開啟 JSON 右方 | 依勾選圖資進行AI分析 | 顯示圖層跨專案／工作區整合；隱藏及隱藏來源衍生圖層排除 |
| 記錄 → 匯出全部紀錄右方 | 依勾選紀錄進行AI分析／依全部紀錄進行AI分析 | 合併完整紀錄文字、簡短摘要、時序／比較表與三點資深審計查核建議 |
| AI 空間助理分析成果 | 點擊三點建議或輸入後續問題 | 沿用該次來源，重新查核並回報成果；執行期間顯示階段進度 |
| 地圖上的導航路線／模型 | 點擊 → 關閉這條導航路線 | 只停止並隱藏該條路線，保留方案；重新展示可恢復 |
| AI 智慧大眾運輸 | 新範例 → AI 規劃 | 清除前趟條件但保留乘客／票價偏好；表格呈現實際方案及票價依據 |

## 範例 6 失敗原因及修正

- 新範例過去只換自然語言文字，可能仍保留上一趟解析後的車站、停留點及期限。
- 「台北車站」物件可能帶著羅東舊座標，導致判斷成羅東到羅東、無班次。車站名稱優先比對官方站號／座標。
- 市名與車站區分：宜蘭／台北未明指車站時使用行政地區中心，不把名稱猜成錯誤 POI。
- MaaS 回傳缺少路線幾何的部分方案時，保留該方案與原因，另查官方公開班表，完整方案優先。
- 抵達模式反推起站步行、五分鐘進站緩衝與車次；不把指定抵達時間當成出發時間。
- 重複診斷訊息去重；同條件兩次失敗停止重複 TDX，改查官方來源，不偽造班次或放寬使用者限制。

## 圖資分析驗證與統計定義

- 使用明確標註的人工驗證面與點線樣本，並加入另一個工作區 GeoJSON，非使用者正式改善潛力分區。
- 範圍為宜蘭縣政府附近約 0.01 km²；實際向官方 NLSC 分棟服務取得 BUILD_ID，來源為 `https://3dtiles.nlsc.gov.tw/building/tiles3d/36/tileset.json`，模型屬性日期 202311。
- 瀏覽器結果：範圍內設施 2 點、其他工作區 2 點、自行車道 1 線圖徵、建物 1 棟、自行車道兩側各 30 公尺內 1 棟；隱藏驗證點不納入。
- 點擊「查核自行車道兩側 50 公尺建物」後重新計算，回報 1 棟、限制、來源與可調閱證據；免費模型有失敗輪替，最後取得正常回覆。
- 面範圍優先採名稱含「高改善潛力」的所選面圖資，否則採所有所選面圖資；線與點以相交計數，不等於唯一營運路線或站牌。
- 3D 建物不是數畫面圖磚：依官方 BUILD_ID 去重，以中心落在面內及中心至自行車道的地表距離判定。不是建物足跡相交、工程安全距離或全縣完整建物清冊。
- 大於官方單次 2 km² 上限的面切成小區查詢；完整回覆快取 30 分鐘。缺漏、未知、超過四項模型來源與缺少來源網址會明示，未知不當成零。
- 地形／影像等服務參照沒有分析向量，明示不能從畫面推算數量。

## 紀錄分析與回報

- 完整 Markdown 文字依來源紀錄、儲存時間逐段處理，每個區塊保留來源編號與臺灣 UTC+08 時間；大量資料採階層摘要，沒有只截取前段原文。
- 專用審計分析範圍避免把無關票價／班次當成每份紀錄必要條件；不把原對話建議當成已執行成果。
- 舊紀錄若含內嵌 base64 影像／附件，二進位編碼替換為索引，可讀文字完整保留；不當成加密字串，也不要求解密金鑰。ISO 的 Z 為 UTC，檔名是臺灣 UTC+08，八小時差不作為資料矛盾。
- JSON 附檔、影像與影片只列索引，本次分析範圍為紀錄文字；語意模型失敗會列出未完成區塊及結構摘要，不假稱全部語意查核完成。
- 瀏覽器選取本次功能驗證紀錄，完整兩個文字區塊後產製摘要、比較表、三點建議及來源表；已點擊「整理原始證據調閱清單」，再讀完整兩區塊並回報時序、應調閱文件／目的／負責單位／缺口表及三點建議。

- 另以「依全部紀錄進行AI分析」整併四筆既有功能驗證紀錄，處理五個可讀文字區塊，回報跨紀錄時序／類型／數據表、三點建議與四筆來源清單。舊 CCTV 影像編碼已索引化，未要求解密金鑰；臺灣時間顯示正確。
- 模型摘要與查核建議仍須對照來源紀錄；實際圖徵數及票價以結構化計算表為準，不把語意模型的推論當作官方認定。

## 實際資料限制

- 官方班表備援目前是臺鐵搭配核實步行接駁，不是全運具完整最短路徑搜尋。「最省錢／最快」僅在取得且符合限制的候選方案中比較，不能保證全球最優。
- 班表是公開的預定時刻，路線及 3D 模型為行進示意，不代表即時位置或剩餘座位。
- 官方票價不足時依已確認官方費率及路徑里程提供估算，表格標示估算、來源、生效日期與驗證時間；不讓 LLM 猜金額。
- 使用者正式 JSON 分區未作為本次樣本輸入；不能把上述一棟驗證數量當成使用者專案的正式成果。
- 本次沒有重驗實體語音、CCTV、錄影或空拍功能。
