# 宜蘭地籍航照風險選案｜使用者操作 SOP

適用版本：第二階段「AI 清冊與航照智慧勾稽」＋第三階段封存／盲測工具（2026-10-27）。
成果性質一律是 **AI 候選，非正式現勘結論**：分數不是違規機率，影像判釋不等於法律結論。
清冊、地籍、航照、照片與分析結果只留在本機 `data/local`，不進 Git、不送外部 AI。

## 0. 前置檢查（每次開工）

1. 雙擊 `啟動上帝之眼-瀏覽器版.bat`。Chrome 會開 `http://127.0.0.1:4175/`，服務只綁本機。啟動失敗看 `logs/browser-launch.log`。
2. 確認本機服務與地籍庫就緒（擇一）：
   - 瀏覽器開 `http://127.0.0.1:4175/api/taiwan/nlsc-buildings/info/cadastre/status`：應看到 `available: true`、`parcels: 532377`、`latestDataDate`（民國 115 年 5 月 1 日）、12 個鄉鎮市與 `source`（使用者提供之 shapefile，本機匯入）。
   - 或命令列 `node scripts/phase3-acceptance.mjs`（會連同抽查地籍定位）。
3. 地籍已匯入就**不要重複匯入**（`data/local/cadastre-yilan.sqlite`，約 290 MB；重建要執行 `scripts/build-cadastre.mjs`，約 13 秒，但沒有必要）。段名對照表在 `data/local/cadastre-sections.json`，缺少時執行 `node scripts/fetch-cadastre-sections.mjs`。
4. 授權提醒：地籍圖為使用者提供資料，僅供本機；航照用國土測繪中心 PHOTO2 現況影像（政府資料開放授權），快取只在本機。

## 1. 單筆查詢（例：宜蘭縣／五結鄉／季新段／34 地號）

1. 工具列「AI」→「AI 清冊與航照智慧勾稽」。
2. 區塊 A：鄉鎮市選「五結鄉」，地段填「季新段」，地號填「34」（子號用 `268-1`）→「自動取得航照並分析」。
3. 會開「查核卡」，確認：
   - 航照實圖上有黃色宗地邊界；
   - 影像來源（PHOTO2 WMTS）、**拍攝日期：未知**（服務不提供，不會用取圖時間冒充）、系統取圖時間、解析度、授權、影像雜湊；
   - 單一宗地沒有清冊文字，所以 R09 會標「不可評」，只有空間與影像統計；
   - 地段或地號不存在會直接報錯，不會捏造結果。

## 2. 完整批次（匯入檔案1）

1. 區塊 B：選 `檔案1_宜蘭縣高風險案件清冊_3,902筆.xlsx` →「匯入清冊」。
2. 核對：高風險案件 3,902、未命中清冊 3,446、解析錯誤 0；展開「欄位對應畫面」確認每個欄位對到正確的來源欄（可改選後「套用欄位對應並重新解析」）。
3. 範圍選「高風險案件」，取圖筆數建議「前 100 筆」→「開始 AI 智慧選案」。進度分成：
   - 已處理（文字＋地籍定位，全部 3,902 筆）；
   - 成功取得航照／缺圖或取圖失敗（只算實際取得且可用的）；
   - 查證照片已讀取／照片失效；
   - 不可判讀（航照與照片都不可評）；
   - 歷年航照：待授權／未介接（目前一律未介接）。
   可隨時「停止」；「重試失敗項」只重做失敗的；「復原航照結果」把航照與照片結果退回只有文字與地籍的狀態。
4. **正式盲測前先封存**（見第 4 節）。

## 3. 檢查結果

1. 「現勘地點排序」切換 Top 12／Top 30／全部；「逐筆案件」可搜尋編號、地籍、文字。
2. 點任一列開查核卡，回查：原 Excel 列號、地籍比對（含舊段名提示）、航照與宗地界線、原查證照片、規則抽取證據（底色標示）、R01～R10 與 R09-A/B、風險構成與算法版本、資料缺口、待調文件。
3. 在查核卡下方做人工覆核（待覆核／建議現勘／待調證／不需現勘），會留稽核紀錄。
4. 匯出：Top 選擇後按「匯出 Excel／GeoJSON／evidence_manifest.json」；也可命令列 `node scripts/export-candidates.mjs 12 high`（輸出到 `data/local/inventory/outputs`）。圖面都是真實取得的航照，沒有示意圖。
5. 權重：展開「評分規則與權重」可調整，會自動重算排序並寫入稽核紀錄（`/api/taiwan/inventory/audit`）。**盲測期間不要改權重。**

## 4. 封存與盲測對照

1. 第一次正式選案完成後，封存排序（不可改寫）：

```bash
curl -X POST -H "Content-Type: application/json" -d "{\"scope\":\"high\"}" http://127.0.0.1:4175/api/taiwan/inventory/seal
```

   回傳 `runId`、`snapshotSha256`。快照含來源 SHA-256、演算法版本與權重、前 12／前 30／全部排序、機器與性能。**封存前不要讓模型或程式讀檔案2。**
2. 封存後才進行對照（獨立驗收工具，只讀快照與檔案2，不回寫）：

```bash
node scripts/blind-compare.mjs <runId> "D:\路徑\檔案2_宜蘭現勘12處逐筆勾稽清冊.xlsx"
```

   輸出 `data/local/inventory/seals/blind-<runId>.json`，內含 Top 12／Top 30／全部的處數與逐筆召回、三種比對 key、失敗原因。
3. 封存之後才做的重跑，要加 `"file2Read": true` 封存，並用 `--supplementary` 比對；這類結果不能稱盲測。

## 5. 未命中清冊（補充選案）

1. 範圍選「未命中清冊」→ 開始 AI 智慧選案。
2. 限制：該工作表**沒有座標也沒有照片網址**，只能依參考地籍文字找宗地，因此不做 50 m 跨期鄰近；GeoJSON 沒有點位。若要完整比對，請補原始 7,348 筆母體（含座標與照片）。不會捏造欄位。

## 6. 異常情形怎麼辦

| 狀況 | 畫面／行為 | 你要做的 |
|---|---|---|
| 無網路 | 航照「取圖失敗」、照片「照片失效」，文字與地籍分析照常 | 網路恢復後按「重試失敗項」 |
| 照片 403／429／非影像／損毀 | 該張標失敗並寫原因，R09-A 為不可評 | 重試或人工調閱 |
| 航照服務限流 | 圖磚自動重試 3 次，仍失敗標「部分取得」或「失敗」 | 稍後重試，不要連續大量取圖 |
| 舊段名（重測前） | 地籍比對標「疑為舊段名」並提示現行名 | 以新舊地號對照表人工確認 |
| 座標與地號不符／跨宗地 | 標「待查」，不自動改地號 | 人工以謄本與圖面確認 |
| 拍攝日期未知 | 顯示未知；R09-B 附「非同期、不能推斷新增／拆除」 | 需要同期影像時另行取得合法歷年航照 |

## 7. 不要做的事

- 不要把 `data/local` 或匯出檔上傳 Git／雲端；不要把清冊貼給外部 AI。
- 不要把「色彩粗檢一致」當成現場一致，也不要把分數當違規機率。
- 不要在盲測前讀取檔案2或根據它調整權重。
