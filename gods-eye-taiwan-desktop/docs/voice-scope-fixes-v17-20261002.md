# v17 語音區域載入修正與驗收（2026-10-02）

## 原因

原流程只記範圍狀態，未保存完整待執行請求；scope漏傳及逐字稿先後順序被誤判為未確認。實際Gemini Live抽測也發現「載入」變成「再入」、「新北市」變成「心北市」，以及簡體逐字稿不能對上繁體圖資名稱。

## 修改

1. 保存圖資、操作、問題與回合識別，接續正式22縣市／全台灣回答；模型清單也提供待補請求。
2. 從使用者逐字稿擷取唯一有效區域，補上漏傳或不符的scope。已指定就直接執行；未知、否定及不明確範圍不自行猜。
3. 保留回合逐字稿，等待獨立到達的ASR片段，模型回合結束不清空原文。模型只詢問或漏呼叫工具時，host可接續明確請求。
4. 輸入辨識提示zh-TW與官方地名／圖資詞彙；繁簡字與有限已觀察同音誤字統一對照，不任意以近似字猜縣市。
5. 同回合去重、兩分鐘期限、停止與取消清除，新請求取代舊請求。保留來源範圍建議及固定版／手動更新區別。

## 已完成驗收

- JavaScript語法及前端正式建置。
- 22縣市、全台灣、繁簡字、否定範圍與多縣市不誤判。
- 完整指令、scope漏傳／與逐字稿不符、兩回合接續、去重、取消及停止。
- 實際控制器事件重播：逐字稿分段、工具先於ASR、ASR在回合結束後到達，以及模型沒有工具呼叫。
- 實際Gemini Live，Windows繁體中文合成語音、正式SDK及既有短效權杖服務：
  - 「請幫我載入道路中心線」→詢問→「全台灣」：osm-roads／taiwan。
  - 「請直接載入宜蘭縣的河川水系中心線」：osm-waterways／宜蘭縣，直接執行。
  - 「請幫我載入道路中心線」→詢問→「新北市」：osm-roads／新北市。
- 真實語音辨識及模型工具呼叫經過本次控制器；載入介面以替身記錄目標、範圍與fresh=false，沒有加入使用者測試圖層、沒有改寫服務金鑰。音檔及結果留在本機logs/qa-v17，不提交GitHub。
