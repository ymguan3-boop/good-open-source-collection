# v28 AI 空間助理與大眾運輸修正確認

日期：2026-10-06。更新範圍為文字助理回覆驗證、免費模型輪替、需求解析與旅程問題確認；既有票價來源、Blender 模型及單一 Cesium Viewer 架構沿用。

## 已確認原因

1. `/models` 舊清單只驗證零價格與文字輸出，把 `nvidia/nemotron-3.5-content-safety:free` 納入一般助理；自動 router 也可能回傳分類。串流只對旅程比較檢查安全分類，普通 GIS 對話把分類當回答。
2. 公共運輸需求解析固定 `.slice(0,3)`、18 秒單次與 50 秒整體期限；旅程補充對話亦限定三個模型。範例 5 含中繼及期限，完全依賴外部模型。
3. 推理與可見回答共用 completion budget，原本 `max_tokens:1800` 配 `reasoning.exclude:true` 仍可能只留下短標題；finish_reason=length 也被當作成功。本次真實首輪僅回44字標題，追修後取得395字完整分析，區分已載入12筆公開測試道路資料、沒有既有計算與待驗推論。Gemma實測HTTP429；Apodex實測HTTP200，非金鑰401。

## 修正流程

公開模型清單 → 零費用一般文字模型 → 支援能力相容的推理設定 → 回覆完整性／分類驗證 → 成功才提交回答；失敗繼續輪替清單。可停用推理的模型不開啟推理；mandatory 模型依支援的較低 effort 或 reasoning budget 設定，不強送不存在選項。

自然語言 → 明確本機解析／SSE 外部解析 → TripPlanningRequest → 語法及時間檢查 → 官方地點與班次 → 正式結果，或三項修正建議 → 使用者確認 → 套用補正 → 重新查詢。

- 免費模型不再限三個；清單內合適模型逐一嘗試，成功即停止。
- 單次模型與清單查詢仍有逾時，取消／關閉中止工作；全清單不可用、憑證失效或官方資料缺漏不是可保證靠重試修好的情形，保留原條件並進入修正確認。
- 安全分類與被截斷回覆不寫入有效對話／分析報告；失敗的串流草稿會清除。
- 支援結構化輸出但回HTTP400的模型，改用純JSON一次，仍經同一欄位schema驗證，禁止AI提供票價、班次或座標。
- 單一中繼的明確描述可直接解析，不問票種以外的無關問題；無日期不能靜默決定今天或明天。範例5會提出三項日期修正建議。
- 三項建議含具體條件補正或返回已填表單，保留成人／兒童、人數、中繼點及停留。點按與自然語言確認共用revision檢查，舊建議不會改寫新旅程。
