# v34 空間批次引擎、紀錄索引與分析插話

日期：2026-10-07。依使用者兩份交接附件改善既有介面；沿用原 Cesium 地圖、圖資、對話與 Markdown 匯出。

## 工作流程

勾選可見圖資 → 資料雜湊 → 範圍索引 → 合併查詢網格／選取範圍 union → 官方分棟資料快取 → 索引候選篩選 → 精確套疊與 BUILD_ID 去重 → 彙整 JSON → 一次 AI 解讀。

紀錄 → 首次摘要與 metadata 索引 → SQLite / FTS5 檢索 → 最多10筆摘要 → 有限字數的結構化輸入 → 一次 AI 解讀。全文與媒體留在瀏覽器，開啟及匯出時才載入。

LLM 不接收大量座標、不逐 Feature／Polygon／建物呼叫工具；統計、比較數字由本機表格顯示。AI 解讀要求不重述數字，若仍出現未核對數字或不存在的來源編號，採用本機摘要與查核方向，避免呈現錯誤統計。免費模型失敗時仍沿用既有模型輪替，這不代表逐筆分析。

## 模組

| 模組 | 工作 |
| --- | --- |
| spatialBatchCore.js | 分層包圍盒索引、精確候選套疊、線走廊距離、來源識別碼去重 |
| spatialAnalysisEngine.js | 共用查詢網格、合併選取面、限制並行量、雜湊與 TTL、摘要上限 |
| spatialAnalysisWorker.js | 大量運算移到 Worker，保持輸入與地圖控制可用 |
| selectedLayerAnalysis.js | 排除隱藏圖層與父層隱藏、來源 metadata 與本機統計表 |
| nlscBuildingAnalysis.js | 同一 GLB 的下載合併與解析後 metadata 快取；不以展示圖磚數推定棟數 |
| recordRetrieval.js / recordIndex.js | 舊紀錄索引、SQLite metadata、FTS5 trigram、事件關聯表、TopK、離線摘要備援 |
| recordAnalysis.js | 摘要檢索、來源索引、全文明確要求、輸入字數上限；移除逐段模型迴圈 |
| chatArchive.js | 摘要分頁、搜尋與條件、延遲原文／媒體載入、CCTV代表截圖 |
| ui.js | 分析工作、插話及取消各自管理；最終結果與可點擊查核建議 |

## 可調整門檻與快取

`SPATIAL_DEFAULTS` 定義於 spatialAnalysisEngine.js；本機 `gev.tw.spatialAnalysis` JSON 可覆寫設定。

- 任一門檻達到即交 Worker：5,000 筆圖徵或200個面分區。
- 網格預設900公尺，查詢先裁切至所選面聯集；過長幾何才退回網格外框，計數仍精確篩回所選面。
- 官方查詢預設並行3個，最多4個；幾何不得超過既有官方代理面積／大小限制。
- 網格快取預設30分鐘、最多1,024項；完整計算快取最多4份。
- Worker 保留近期來源索引，閒置2分鐘釋放；停止立即終止 Worker。
- 官方 GLB metadata 最多128項／120,000筆分棟資料，同一下載進行中會合併。
- 完整結果才進成功快取；異常／部分資料保留警告，不把未取得當作零。
- AI 空間摘要最多60列／30項來源，省略數量明示，完整本機表保留；無逐筆座標。
- 紀錄預設最多10項摘要，結構化輸入上限約12,000字元；超過時縮減摘錄並保存省略數。原文要求也受輸入上限約束，不宣稱讀過未送出的全文。

## SQLite 與舊紀錄

- 檔案：使用者 LocalAppData/GodsEyeTaiwan/records/index.sqlite；只在本機儲存摘要／metadata／事件關聯，不寫入 GitHub。
- `records`：namespace、來源ID、時序、類型、地點、專案、攝影機、hash、摘要、metadata。
- `record_fts`：FTS5 trigram 摘要檢索；`cctv_events`：同攝影機／事件／時間窗關聯。
- 瀏覽器 Dexie v4 新增 recordIndex；原 chatRecords 保留。首次以25筆批次補索引，之後只讀 metadata，不反覆讀全部 Markdown。
- 正常清單由 SQLite 每頁50筆查詢；離線時可用瀏覽器摘要索引。勾選跨頁保留，分析只傳來源識別碼。
- 查詢及來源條件使用 SQL 參數；僅既有 localhost 同來源 API 可讀寫，namespace 隔離瀏覽器資料。
- Node 24.14.1 已驗收內建 node:sqlite。較舊 Node 缺少 SQLite 時會顯示瀏覽器摘要備援；建議使用安裝流程支援的新版 Node。
- Hot24小時／Warm30天／Cold更早為邏輯分級；原文未自動搬移或刪除，可用既有 ZIP 匯出保存。
- CCTV 不逐影格呼叫外部模型。相同相機／事件60秒內合併索引，最多保留首／中／尾3張代表截圖；原始文字、事件來源與時間仍保留。既有媒體不在本次移除。
- 向量搜尋不是本次必要依賴，採 FTS5＋metadata 完成 P0；未額外引入付費 embedding 或新資料庫服務。

## 分析中插話

- 「剩多少還沒分析？」立即回答階段、已完成／剩餘工作單位及經過時間；沒有可靠單位時明示，不猜剩餘秒數。
- 補充意見納入最終解讀；可辨識的兩側走廊公尺設定交引擎重算，沿用官方查詢快取。
- 一般提問可獨立回答，背景分析繼續；修改最終解讀條件時取消舊解讀並依最新要求產出。
- 「停止分析」取消網路、Worker及模型；保留已完成階段。工作已結束時不會因停止指令重啟。
- 原先最後一輪進度逐分區重繪改為階段摘要與約400ms節流，減少對話 DOM 成長。

## 本輪交通及介面修正

- 範例10以明確重新規劃解析保留起點、途經點、乘客及運具；缺少起點時先詢問。建議的 clarify/edit 動作都有對話回覆；直接回覆地點可接續規劃。
- 臺鐵先查指定日期 DailyTimetable 中存在的車種；不可用時明示官方目錄與日期不足。選擇使用官方名稱識別，避免 TDX 與官方 ODS 的不同代碼造成全數排除。
- 有車次時用該車次及同一起訖核對，避免 MaaS時間格式微差；只排除明示停駛的班次。全部可搭不因不熟悉的列車名稱一律判為車種不符，未確認計價類別不套票價。
- 高鐵沿用官方可確認車廂票價，公車依業者／路線／站序，捷運輕軌依系統及起迄，自行車依系統／時間；未增加無意義車種選項。
- 不由 TrainTypeCode 猜特殊車廂能力；來源沒提供能力時不顯示虛構座位選項。
- 專案、紀錄、圖資主要按鈕共用水平排版與對比；圖資刪除「開啟JSON專案」，專案仍可開啟JSON。圖資各類別及子層級可折疊並保存狀態。

## 驗收紀錄與限制

| 抽查 | 成果 |
| --- | --- |
| 合成400個分區、20,000個點 | 獨立矩形比對與索引計算均為 18,000 個相交點 |
| 候選篩選 | 可能的8,000,000組逐項配對，實際精確核對 18,000 次；不是用簡單矩形測試宣稱任意幾何加速倍數 |
| 合併官方查詢測試替身 | 400分區合併成 9 次網格查詢；同條件快取新增查詢0次 |
| SQLite | 1,000筆隔離測試紀錄，Top10與勾選來源限制正確 |
| 真實 NLSC 小範圍 | 直接查核及批次均 1 棟，complete=true；生活設施2筆、自行車道1線；隱藏點排除 |
| 瀏覽器 | 400分區觸發 Worker；進度插話回覆、50公尺條件補充與停止有效；停止後不重啟；勾選單一驗收紀錄完成 SQLite 摘要檢索及自動成果回報 |
| Build | Vite正式建置含獨立 spatialAnalysisWorker；既有大bundle警告仍存在 |

- 合成測試不是宜蘭全縣實測；真實官方模型抽查只涵蓋人工小範圍，未宣稱全部最小統計區或全縣完整建物清冊。
- 同時開啟大量 Cesium 圖徵仍可能有展示記憶體成本，本次改進分析計算與摘要流程，未重建地圖或壓縮原始來源。
- 官方來源逾時、部分GLB欠缺分棟屬性／模型版本不符，仍可能缺資料；此時如實標記部分／未知。
- 本機快取依資料內容與TTL，官方模型有效版本仍依來源；不能等同即時現況。
- AI回覆可能受免費模型服務可用性影響；本機統計先保留，未以模型推算填缺數字。

技術參考：[Node SQLite](https://nodejs.org/api/sqlite.html)、[SQLite FTS5](https://www.sqlite.org/fts5.html)、[TDX官方API文件](https://tdx.transportdata.tw/api-service/swagger)。
